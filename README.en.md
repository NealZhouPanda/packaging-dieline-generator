# Packaging Dieline Generator

English | [中文](README.md)

An offline-capable packaging dieline generator: enter box dimensions and board thickness, and the dieline is computed locally in your browser, exported as a 1:1 mm SVG or a PDF with an info strip. The released artifact is a single HTML file — double-click to use, no runtime installation required, and no dimension data ever leaves your machine.

Try it online: <https://nealzhoupanda.github.io/packaging-dieline-generator/>

> This is an assistive tool for practical proofing and pre-production checks. It does not replace structural confirmation, trial folding, or process review by a corrugated/paper box manufacturer.

## Current Capabilities

`index.html` together with `src/` is the single source of truth; `app/包装刀模生成器.html` (the offline app), `release/包装刀模生成器.html`, and `docs/index.html` are all generated by the build script and must not be edited by hand. Five box styles are currently included:

- `0201`: standard slotted box (FEFCO 0201 / RSC)
- `0421`: flip-lid display box
- `K016A`: handle box
- `E005C`: flip-lid aircraft box (0427)
- `C001GX`: flip-lid lock-bottom box

Inputs are length, width, height, and material type. Corrugated board shows its flute profile; white cardstock shows a separate caliper field. The UI supports opening-orientation switching, blank-size hints, dimensional-weight estimation, container loading estimation, and SVG / PDF export. The area and per-sheet count shown under each opening orientation are estimated from the dieline bounding envelope; "per sheet" means how many boxes can be cut from one sheet of the base paper and can be used for material and cost estimation. Independent per-style paper calibration is still being expanded. Container loading estimation supports 20GP, 40GP, 40HQ, and 45HQ: it computes the theoretical maximum load by arranging the box's outer dimensions in all six orientations and taking the largest floor-stacked count, then multiplies by a 0.88 practical load factor for the displayed estimate.

Switching box styles loads presentation defaults: `0201` defaults to 350×190×230 mm / A-flute corrugated 5.0 mm, `E005C` to 350×190×230 mm / B-flute corrugated 3.0 mm; the `0421` display box and the `C001GX` lock-bottom box support white cardstock at 0.4, 0.5, 0.6, 0.8, and 1.0 mm. Cardstock thicknesses are presentation defaults; for production, adjust to the board's measured caliper from your supplier.

The top-right `EN / 中文` toggle switches the main UI language; the language layer never participates in dimension or dieline calculations.

## Style Numbering

Style numbers prefer established industry codes. `0201` follows the FEFCO 0201 coding for regular slotted containers (RSC). Where a structure has no confirmed public industry code, the project keeps its own identifier rather than presenting a vendor-internal number as an industry standard.

## Important Notes

- Dimension formulas apply only to their matching box style; do not carry one style's compensation rules over to another.
- Proof before first production run: verify internal dimensions, dieline size, board thickness, creases, and the folded result.
- The geometry of 0201, E005C, and C001GX comes from the current single-file application; any new box style must add its own coordinate calibration and regression tests first.
- New styles still need independent structural samples and production validation; the area shown for each opening orientation is a bounding-envelope estimate displayed together with the per-sheet count, and is not a precise material figure until per-style net-area calibration is complete.
- Per-sheet counts estimate against paper sheets by material: 1200×2400 mm for corrugated board, 889×1194 mm large-format flat sheets for white cardstock; results differ with the supplier's actual sheet size.
- The material-size warning is a pre-production hint only, not a universal limit across supplier equipment.

## Development

Requires Node.js and npm:

```bash
npm ci
npm test
npm run build:offline
```

Build output:

```text
release/包装刀模生成器.html
```

To open the dev page:

```bash
npm run dev
```

## Layout

- `index.html`: the dev page and the single entry point for the UI structure
- `app/`: the single-file offline app generated from module sources; do not edit by hand
- `src/`: modular geometry, SVG / PDF export, and code used by regression tests
- `tests/`: geometry, dimension, export, and safety-gate tests
- `reference/`: local regression and calibration data
- `tools/`: single-file build and PDF font-subset build scripts
- `release/`: offline HTML generated in sync with `app/`, ready to share directly
- `CONTRIBUTING.md`: collaboration and verification requirements

## Contributing

Any change to geometry rules must update the tests in the same change and pass `npm test` and `npm run build:offline`. Never claim a box style is production-ready without proofing or independent coordinate verification.
